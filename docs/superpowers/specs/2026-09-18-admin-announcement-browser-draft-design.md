# 管理员公告浏览器草稿设计

## 范围

只改 Vue 管理员公告编辑页。管理员可手动保存尚未发布的新公告或尚未提交的公告修改，并在同一浏览器、同一账号下重新打开对应编辑器时恢复。草稿仅保存在 `localStorage`，不新增后端接口、数据库表或用户端展示。浏览器数据被清理或换设备后，草稿不可恢复。

## 数据与隔离

- 存储键采用带版本的固定前缀，加管理员 `userInfo.id`，再加 `new` 或公告 ID；新建与每条已有公告相互独立，不同管理员也相互隔离。只有管理员角色且有有效账号 ID 时显示和启用草稿操作。
- 每份记录只包含 `title`、`content`、`appVersion`、`draftToken`、保存时间，以及草稿所属的新建/公告 ID；不存 JWT、AccessKey 或图片二进制。读取时验证记录结构和归属，损坏记录当作不可恢复。
- `draftToken` 随记录保存和恢复，确保此前上传的图片仍可在正式提交时由后端关联。新建公告若有本地草稿，在用户选择恢复前先使用临时生成的 token；选择恢复时一并替换。编辑已有公告亦如此。

## 交互与状态

- 在公告编辑弹窗内添加“保存到浏览器”按钮；点击时保存当前表单并反馈时间或成功提示。图片正在上传时禁用保存、关闭和正式提交，避免截取不完整的 Markdown。
- 打开新建或编辑弹窗时，默认先显示空表单或服务器公告内容；若当前账号、对应公告的草稿存在，展示“发现本地草稿”提示及“恢复草稿”“舍弃草稿”操作。恢复会覆盖当前弹窗字段；舍弃只移除这一条本地记录，不更改服务器公告。
- 关闭弹窗不自动覆盖或删除草稿。发布或更新接口成功后，立即移除对应草稿；请求失败时保留草稿和编辑器内容。删除一条公告成功后，清除该公告在当前管理员账号下的本地草稿。
- 存储不可用、空间不足或写入失败时显示失败提示，不宣称已保存；格式错误的草稿不会让公告页崩溃。恢复后仍须点击原有“发布公告”或“保存修改”才会发送后端请求。

## 验证

人工检查新建及编辑两种草稿各自的保存、刷新后恢复、账号隔离、`draftToken` 恢复、发布成功清除、发布失败保留、浏览器存储失败提示；运行前端构建。按用户要求不运行自动测试或浏览器自动化。
