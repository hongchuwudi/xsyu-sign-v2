# 管理员操作日志 AOP 增强设计

## 目标

只扩展现有 `@LogRecord` 和 `OperationLogAspect` 日志链路，让管理员操作日志页面能够查看和检索更完整的登录、签到信息，不增加新的业务事件系统，也不扩大服务器控制台日志量。

## 范围

- 登录日志：密码、短信、扫码和管理员本地登录。
- 签到日志：用户一键签到、管理员代签和单项签到。
- 管理员操作日志页面及其分页查询接口。
- 保留现有定时任务、间隔签到和 JWS 续签日志的兼容性。

不记录或展示密码、短信验证码、图形验证码、JWT、JWSESSION、Cookie、Authorization 请求头以及任何密钥。

## 数据结构

在 `operation_log` 表增加以下可空字段：

- `user_id BIGINT UNSIGNED`：目标用户 ID，与现有 `user.id` 类型保持一致，但不创建外键，避免用户删除后历史日志丢失。
- `username VARCHAR(64)`：学号或管理员用户名。
- `user_name VARCHAR(100)`：操作发生时的姓名快照。
- `action_method VARCHAR(32)`：`PASSWORD`、`SMS`、`QR`、`MANUAL`、`ADMIN` 等操作方式。
- `request_uri VARCHAR(255)`：触发日志的接口路径。

增加面向时间、学号、结果和类型的查询索引。原有 `operator`、`detail`、`ip`、`duration` 等字段继续保留。

## AOP 数据提取

`OperationLogAspect` 在方法执行前后统一收集上下文：

1. 从登录 DTO、路径参数或 `BaseContext` 获取学号和用户 ID。
2. 登录成功时优先从 `UserLoginVO` 获取用户 ID、学号、姓名和角色。
3. 登录失败时按 DTO 中的学号查询已有用户，补充用户 ID 和姓名；不存在时只记录学号。
4. 签到接口按当前用户 ID或管理员代签路径中的学号查询用户信息。
5. 根据接口路径识别登录或签到方式。
6. 保存 HTTP 方法、请求 URI、客户端真实 IP、耗时、结果和异常消息。
7. 参数摘要使用白名单提取，只记录学号、签到 ID、学校 ID等非敏感业务字段。

二维码轮询处于等待状态时不产生操作日志，只记录最终成功或失败结果，避免管理员页面被轮询日志淹没。

## 日志详情

登录详情至少包含：

- 登录方式
- 学号、姓名、用户 ID
- 用户角色
- 成功或失败结果
- 失败原因
- 请求 IP、接口和耗时

签到详情至少包含：

- 签到方式
- 学号、姓名、用户 ID
- 单项签到的 `id`、`signId`、`schoolId`
- 一键签到返回的处理摘要
- 成功或失败信息
- 请求 IP、接口和耗时

受“只扩展 AOP”的约束，一键签到只能记录控制器最终返回的整体摘要，不在业务循环内部生成逐活动结构化日志。

## 查询接口与页面

`GET /admin/operation-logs` 增加可选参数：

- `keyword`：匹配学号、姓名、操作名称、详情和 IP。
- `result`：`SUCCESS`、`FAIL` 或 `PARTIAL`。
- `actionMethod`：登录或签到方式。

管理员页面增加关键词、结果和方式筛选。列表中的操作人区域改为显示姓名和学号；详情弹窗展示用户 ID、姓名、学号、方式、请求路径、IP、耗时、结果和完整详情。现有日期、类型、分页、批量删除能力保持不变。

## 兼容与错误处理

- 新字段全部可空，历史日志仍可正常展示。
- AOP 查询用户信息或写入日志失败时不得影响原业务请求。
- 日志详情限制长度，防止异常响应或返回内容无限增长。
- 不对 `operation_log.user_id` 创建外键。

## 验证

- 后端执行 `mvn package -DskipTests`。
- 前端执行 `npm run build`。
- 静态检查登录和签到日志中不包含敏感字段。
- 不运行 Playwright。
